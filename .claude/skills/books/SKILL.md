# 読書外部脳スキル（books）

オーナーが過去に読んできた本を「判断軸のライブラリ」として使う。
相談が来たら、**関連する本だけ**を選んで読み込み、その知識を **オーナー自身の経験・現状と統合** して答える。

狙いは、本を紹介することではなく、**本の考え方によって回答の質を上げる**こと。

## 大方針（CLAUDE.md と一致）

- **本を権威にしない。** 「本がそう言うから正しい」とは言わない。本は参考の判断軸。
- **本人を無視しない。** 本の主張だけで答えを作らず、オーナーの過去の経験・今の状況と必ず突き合わせる。
- **捏造しない。** 本に書いていないことを「本に書いてある」と言わない。要約が曖昧なときはその旨を添える。
- **一度に浴びせない。** 引用や要約を長々並べない。会話に自然に差し込む。

## 手順

### 1. 相談テーマを掴む
何についての相談か（お金／仕事／人間関係／健康／時間／自己分析／キャリア 等）と、
相談文に出てくるキーワードを拾う。曖昧なら1つだけ確認する。

### 2. index.md で関連する本を選ぶ（← ここが発火制御の心臓部）
[index.md](index.md) を Read し、相談キーワードと各本のタグを照合する。

- **完全一致だけで判定しない。** 意味的に近いタグも関連とみなす。
  - 例:「32歳の今もっと旅行にお金を使うべき？」→『DIE WITH ZERO』のタグ（経験／若いうちにやる／旅行／お金の使い方／時間）が高く一致。
- **関連度で順位付けし、上位3冊程度だけ**を選ぶ。複数観点が本当に重要な相談のみ最大5冊まで。
- **抽象的すぎるタグ（人生・仕事・人間関係だけ）で大量発火させない。** 具体タグの一致を重視する。
- 「少し関連しそう」程度では選ばない。関連の薄い本は読み込まない。

選んだら、その本の `volumes/<file>.md` だけを Read する。index にない本や全冊は読まない。

### 2.5. ハイライトがあれば一緒に読む（← ここが「本人の琴線」）
選んだ巻の frontmatter に `kindle_highlights:` があれば、そのパス
（`kindle-archive/books/<書名>_<ASIN>.md`）も Read する。**オーナーが実際に線を引いた箇所**が入っている。

- `volumes/*.md` は一般公開の書評から再構成した「**本が何を言ったか**」。
  ハイライトは「**本人が何に反応したか**」。後者のほうが本人の判断軸に近い。
- **両方あるときはハイライトを優先する。** 要約の主張と本人が線を引いた箇所がズレていたら、
  ズレているという事実そのものが情報（本人はそこに刺さらなかった）。要約で上書きしない。
- ハイライトに**本人のメモが添えられていたら最優先**。読んだその場で言語化した本人の言葉なので、
  外部脳として最も価値が高い。
- ファイルが無ければ何もしない（まだ吸い出していない本、紙で読んだ本）。要約だけで答える。

**index.md の63冊に無い本のハイライトもある。** Kindle で線を引いた本と Evernote の「読んできた本」は
もともと別集合で、重なるのは4冊だけだった。Issue #35 で**索引に載せる価値のある7冊を volumes に起こした**ので、
2026-08-27 時点では 35 冊 766 件のうち **11 冊 568 件（74%）が index.md 内、24 冊 198 件が外**。
残った24冊は技術書・資格試験本や、ハイライトが数件しかない本が中心（意図的に起こしていない）。
index.md に効きそうな本が無いとき、または技術・実用寄りの相談のときは
`kindle-archive/book_map.tsv`（1行=1冊の一覧）も眺めて、当たりがあれば
`kindle-archive/books/` の該当ファイルを読む。**要約は無いがハイライトはある**という状態なので、
本の主張を語らず「本人がここに線を引いた」という事実として使う。

**引用の扱い:** ハイライトは書籍本文の逐語。会話に差し込むのは構わないが、
**Podcast / note / ツイートの成果物にそのまま流し込まない**（引用の主従・出典明記に注意）。
このリポジトリは公開されているので、`volumes/` 側へ本文を書き写すことも禁止。

### 3. 本の判断軸を、本人の文脈と統合して答える
選んだ本それぞれから「この相談に効く原則」を1つ引く。そのうえで:

- 本が複数なら、**独立に並べるだけでなく統合する**。
  - 例:「今しかできないことにお金を使うべき？」
    - DIE WITH ZERO → 経験には年齢による賞味期限がある
    - 神時間術 → 時間と身体状態で価値が変わる
    - 本音で生きる → 他人の価値観より自分のやりたいことを優先
    - → これらを組み合わせて1つの判断を提示する。
- 本同士で主張が矛盾する場合は、両方の観点を示したうえで、
  **オーナーの過去の経験・現在の状況**を足して最終的な見立てを1つ出す。
- 引用は最小限。「これは『DIE WITH ZERO』の"経験には賞味期限がある"という考え方と相性がいい」のように会話へ差し込む。

### 4. 必要なら本人の外部脳（Evernote / X）も足す
本の知識だけで足りないとき、Evernote を targeted に `semantic_search` して
**本人の実際の言葉**を1〜2個添えると、より「もう一人の自分」らしい回答になる。重い全走査はしない。

## やらないこと（受入条件より）
- 相談のたびに全部の本を読み込まない。
- 少し関連しそうという理由だけで大量の本を発火させない。
- 本の主張を絶対の正解として扱わない。
- 本の内容だけで答え、本人の経験・状況を無視しない。

## メンテナンス
- 本を1冊足すときは `volumes/` に1ファイル作り、`index.md` に1行足す。
- 1ファイル1冊を厳守（複数冊をまとめない）。
- ファイルの型は既存の `volumes/*.md`（概要／主要な主張／原則／効く相談テーマ／相談例／タグ）に合わせる。
- Kindle にハイライトがある本なら、frontmatter に `kindle_highlights: kindle-archive/books/<ファイル>.md`
  を1行足す。**本文（逐語）は書かない。** 吸い出しの手順は [docs/kindle-export.md](../../../docs/kindle-export.md)、
  索引との突き合わせは `python3 scripts/kindle_match.py`。
- **ハイライトしかない本を新たに起こすときの基準**（Issue #35 で決めた3段フィルタ）:
  ①`books` の趣旨（人生・仕事・お金・人間関係・健康・時間の判断軸）に合うか
  → ②ハイライト25件以上か → ③既存索引でタグが手薄な領域を埋めるか。
  **件数だけで決めない。** 索引は毎回ロードされる固定費なので、既存本と領域が重なる本は増やさない。

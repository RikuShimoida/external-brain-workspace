## 並列開発バッチ（司令塔オーケストレーター）

引数: `$ARGUMENTS`（並列で実装したい Issue 番号の列挙。例: `14 19 20`）

### このスキルの位置づけ

**実装フローの本体は `/impl` が持つ**（worktree 作成・初期化・実装・検証・PR・後片付け）。
このスキルは「複数 Issue を一度にまとめて指示したいとき」に、各 Issue へ `/impl` 相当の手順を
発火させるだけの薄いオーケストレーターである。

> 並列は本来「`/impl` を複数回呼んだ結果として自然に発生する」もの。
> 1タスクだけ、割り込みで1本足すだけなら **このスキルは不要で `/impl` を直接呼ぶ**。

設計の全体像・共有資源の制約は [docs/worktree-workflow.md](../../../docs/worktree-workflow.md) を参照。

### 前提条件（満たさなければ停止）

- `git branch --show-current` が `main`（司令塔）であること。
- 司令塔の作業ツリーが clean であること。
- 並列対象の各 Issue が `/plan` で承認済みであること。未承認があれば先に `/plan` を案内する。

### Phase 0: 適格判定（並列に流していいかを先に決める）

各 Issue について `docs/worktree-workflow.md` §2 に照らして判定する。

- **アーカイブ配下（`*-archive/`）や生成物ディレクトリを書き換えるタスクは並列禁止。**
  これらは全 worktree でシンボリックリンク共有されており、同時に書き換えると壊れる。
  該当が複数あれば、最初の1つだけ走らせて他は待機（直列化）。
- **MCP への書き込み（`post_tweet` / `create_event` / `edit_note`）を含むタスクは並列に流さない。**
  オーナーの承認が前提であり、サブエージェントは承認の窓口を持たない。司令塔で単独処理する。
- 判定に迷う場合は推測せず、「このタスクはアーカイブや生成物を書き換えますか？」とオーナーに確認する。

**判定結果を、着手前に表で提示する。**

| Issue | 判定 | 理由 |
|---|---|---|
| （番号） | 並列 / 直列 / 司令塔で単独 | （共有資源に触るか） |

### Phase 1: 並列実装

- 適格な各 Issue について、`subagent_type: "external-brain-engineer"` のサブエージェントを
  **1メッセージ内でまとめて起動**し、並列に走らせる。
- 各サブエージェントには `/impl` の Phase 1〜2-3 を実行させる。プロンプトに必ず含めるもの:
  - 対象 Issue 番号と、`/plan` で承認済みの計画の要点
  - **作成する worktree のパスとブランチ名**（司令塔が採番し、重複しないよう割り当てる）
  - `main` 起点で `git worktree add` すること、初期化のリンク/コピーを必ず行うこと
  - **アーカイブ・生成物ディレクトリへ書き込まないこと**（必要なら報告して司令塔に戻す）
  - **外部サービスへ書き込まないこと**
  - 最終報告に「変更ファイル・検証結果（実測値）・書き込み要求の有無・残課題・PR URL」を含めること
- 直列判定のタスクは、並列組の完了を待ってから1本ずつ流す。

### Phase 2: 書き込み要求の直列消化（司令塔）

サブエージェントから「アーカイブ / 生成物へ書き込みたい」と返ってきたものは、
司令塔が**要求順に1本ずつ**消化する。同時実行はしない。

- 外部サービスへの書き込み（投稿・ノート更新・予定登録）は、**オーナーに内容を見せて承認を取ってから**行う。
  承認なしに実行してはならない。

### Phase 3: 完了報告

- 各タスクのブランチ名・PR リンク・検証結果を**一覧表**で報告する。
- 直列に回した / スキップしたタスクがあれば理由を明記する。
- 最後に **2択だけ**聞く（3つ以上並べない）。
  1. まとめてマージする（`/merge <PR番号>` を順に実行）
  2. あとで決める（PR 番号を控えて終了）

### アンチパターン

- 複数 worktree で同時に `scripts/*_map.py` / `*_extract.py` を走らせる
- サブエージェントに `post_tweet` / `create_event` / `edit_note` を実行させる
- アーカイブを worktree へ実体コピーする（約1GB）
- 適格判定を出さずにいきなり全部を並列で流す

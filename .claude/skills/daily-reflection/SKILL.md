# 今日の振り返りスキル

オーナーは毎日「今日やること - YYYY年M月D日」ノートを使い、
夜にその日を振り返って「心得、自分を信用するな」の各項目に **⭕️（うまくいった）** か
**❌（失敗した）** を付ける。このスキルは、その丸・罰を決まったルールで別欄へ転記し、
必要ならポストモーテムノートを起票するところまでを**機械的に**代行する。

**このスキルは判断や創作をしない。** オーナーが付けた丸・罰と、手動で書いた文言を
そのまま右から左へ移すだけ。ネタ提案や文章生成は一切しない。

## 大方針（CLAUDE.md と一致）

- **捏造しない。** ノートに無い項目を作らない。丸も罰も付いていない項目は転記しない。
- **記憶を外部化する。** 結果はチャットで流さず、必ず Evernote のノート本体に書き込む。
- **一度に浴びせない。** 完了報告は「何件転記し、ポストモーテムを何件作ったか」の2〜3行に絞る。
- **勝手に突き進まない。** 対象ノートが今日の分か曖昧なとき、丸・罰が1つも無いとき、
  ポストモーテム欄の解釈に迷うときは、実行前にオーナーへ確認する。

## 前提となるノート構造（実物で確認済み）

「今日やること」ノートの中身は ENML。判定に使う要素は次の2つだけ。

- **心得セクション**：見出し `<h2>心得、自分を信用するな</h2>` の直後の
  `<ul style="--en-todo:true;">`。各項目は `<li style="--en-checked:...">`。
  - オーナーは振り返り時に、うまくいった項目の**末尾に `⭕️`**、
    失敗した項目の**末尾に `❌`** を手で書き足す。
  - **チェックの有無（`--en-checked:true/false`）は判定に使わない。** 絵文字だけで判定する。
    （実物では丸付き項目が checked:true、罰付き項目が checked:false のことが多いが、
    これは相関にすぎず、判定基準はあくまで末尾の絵文字。）
- 転記先・記入欄の見出し（ノートによって前後の語が違うので**部分一致**で探す）：
  - `今日、うまくいったこと…`（例: 「今日、うまくいったことと、原因　俺のため」）
  - `今日、失敗したプロセス…`（例: 「今日、失敗したプロセス、原因　俺のため」）
  - `今日、失敗した結果…`（例: 「今日、失敗した結果、原因　俺のため」）※オーナーが手動記入
  - `…残しておいた方がいいポストモーテム`（`<h3>`）※オーナーが手動記入

## 手順

### 0. 準備

必要な Evernote MCP を ToolSearch でロードする（デフォルトで出ていなければ）：

```
select:mcp__evernote__search_notes,mcp__evernote__get_note,mcp__evernote__search_notebooks,mcp__evernote__create_note,mcp__evernote__edit_note
```

### 1. 今日の「今日やること」ノートを特定する

- `mcp__evernote__search_notes` に `intitle:今日やること`、`clientTimeZone: Asia/Tokyo`、
  `sortBy: created` で問い合わせ、**今日の日付（YYYY年M月D日）にタイトルが一致するもの**を選ぶ。
- 今日の分が見つからない、または複数該当して曖昧なときは、**推測で進めずオーナーに確認**。

### 2. ノート本文を取得して心得の丸・罰を抽出する

- `mcp__evernote__get_note(noteId)` で ENML を取る。本文は大きく（5〜6万字）、
  MCP のトークン上限で**ファイルに退避されることがある**。その場合は退避ファイルを
  Python 等で読み、以下を抽出する（チャットに全文を展開しない）。
- **心得セクションの範囲**を切り出す：`心得、自分を信用するな` の見出しから、
  次の転記先見出し（`今日、うまくいったこと…`）の直前まで。
- その範囲の各 `<li>…</li>` について、**内側テキストの末尾に絵文字があるか**を見る：
  - 末尾が **`⭕️`**（U+2B55 [+ U+FE0F]）→ **うまくいった**リストへ。
  - 末尾が **`❌`**（U+274C）→ **失敗したプロセス**リストへ。
  - どちらも無い項目は**無視**する。
- 転記するテキストは、**その `<li>` の可視テキストから絵文字（⭕️/❌）と前後の空白を除いたもの**。
  リンク等のインライン要素は素直にテキスト化してよい（意味が変わらない範囲で）。

抽出は本体コンテキストを汚さないよう、退避ファイルに対して小さなスクリプトで行うのがよい。
目安の判定（Python）：

```python
import re
# li_html = 1項目分の <li>...</li>
text = re.sub(r'<[^>]+>', '', li_inner)          # タグを剥がして可視テキストに
text = text.strip()
if text.endswith('⭕️') or text.endswith('⭕'):
    kind, body = 'ok', text.rstrip('⭕️⭕').strip()
elif text.endswith('❌'):
    kind, body = 'ng', text.rstrip('❌').strip()
else:
    kind = None                                   # 転記しない
```

### 3. 転記先の2欄を書き換える（絵文字は外す・空行は入れ替える）

**うまくいった項目 → `今日、うまくいったこと…` 欄、
失敗した項目 → `今日、失敗したプロセス…` 欄**へ、番号付き箇条書き（`<ol><li>`）で入れる。

- **絵文字（⭕️/❌）は付けずに本文だけ**を入れる（オーナー確定仕様）。
- 転記先にある**既存の空の箇条書き（空 `<li>`）は削除して入れ替える**。
  空でない既存項目があれば消さず、その後ろに追記する。
- `edit_note` の `replace` で、その見出し直後の `<ol>…</ol>` ブロックを
  新しい `<ol>`（番号付き項目群）に置き換える。`find` アンカーは、対象 `<ol>` を
  一意に特定できる**バイト単位で正確なスニペット**（直前の見出しの `--en-nodeId` を含む
  `<h2>…</h2><ol>…</ol>` の並び）を `get_note` の ENML からそのままコピーして使う。
- 該当する絵文字が**片方だけ**なら、その欄だけ書き換える。両方0件なら本ステップはスキップし、
  その旨を報告（丸も罰も付いていない ＝ まだ振り返っていない可能性。オーナーに一声かける）。

### 4. 「失敗したプロセス」に転記した各項目からポストモーテムを起票

§3 で「失敗したプロセス」欄に転記した**各項目ごとに1枚**、その**項目の文言をタイトル**にして
ポストモーテムノートを作る（§7 の手順）。今日 ❌ が N 件なら N 枚できる。

- タイトルは**転記した文言そのまま**（絵文字は既に外れているものを使う）。
- ❌ が0件（＝失敗したプロセス欄に転記なし）なら本ステップはスキップ。
- **テンプレートは無修正・中身も埋めない。** 器を作るだけ。

### 5. 「失敗した結果」→ 記入があればポストモーテムを1件起票

- `今日、失敗した結果…` 欄の `<ol>` を見る。**中身が空（空 `<li>` のみ）なら何もしない。**
- **1つ以上、実テキストの項目があれば**、その**各項目ごとに1枚**、
  ポストモーテムノートを作る（§7 の手順）。ノートのタイトルは**その項目の文言そのまま**。

### 6. 「残しておいた方がいいポストモーテム」→ 記入があれば同様に起票

- `…残しておいた方がいいポストモーテム` 欄の `<ol>` を見る。**空なら何もしない。**
- 実テキストの項目があれば、**各項目ごとに1枚**ポストモーテムノートを作る（§7）。
  タイトルは**その項目の文言そのまま**。

> §4〜§6 はすべて「該当項目があれば各項目1枚ずつ起票、無ければ無視」。
> §4（失敗したプロセス）は §3 の転記結果から自動で、§5・§6 はオーナーの手動記入から。
> いずれも中身は埋めない・テンプレートは触らない。**テンプレートと同じ器を用意するだけ。**

### 7. ポストモーテムノートの作り方（テンプレートを丸ごと複製）

Evernote MCP の `create_note` は**空ノートしか作れず、テンプレート指定ができない**。
そこで「ポストモーテム」テンプレート本体の ENML を丸ごと複製して新規ノートに流し込む。

> §4〜§6 で複数枚起票する場合、**テンプレート本体の取得（手順1）と
> 保存先ノートブックの GUID 取得（手順2）は最初の1回だけ**でよい。
> 取れた ENML を使い回して、枚数分だけ手順3・4を繰り返す。

1. **テンプレート本体を取得**：`search_notes("intitle:ポストモーテム")` で
   `isTemplate:true` のノート（タイトル「ポストモーテム」）を見つけ、`get_note` で ENML を取る。
   - 参照用の GUID メモ（変わりうるので毎回検索で確認すること）：
     - テンプレート本体ノート：タイトル「ポストモーテム」、`isTemplate:true`
     - 保存先ノートブック：「ポストモーテム」
2. **保存先ノートブックの GUID**：`search_notebooks("ポストモーテム")` で
   ノートブック「ポストモーテム」の `notebookId` を得る。
3. **空ノートを作る**：`create_note({ title: <項目の文言そのまま>, notebookId: <上のGUID> })`。
4. **中身を流し込む**：手順1で取った**テンプレートの ENML 本体**（`<en-note>` の
   中身。`<?xml>`/`<!DOCTYPE>`/`<en-note>` タグ自体は付けない）を、
   `edit_note({ noteId, mode: "append", content: <テンプレートの中身> })` で入れる。
   - **テンプレートは修正しない。** 中身も埋めない。テンプレートと同じ器をそのまま作るだけ。
   - ENML が大きいので、必要なら数回に分けて `append` する。

### 8. 完了報告（2〜3行）

チャットには要点だけ返す。例：

> 今日の振り返り、反映しました。
> ・うまくいった 4件 / 失敗したプロセス 4件 を各欄へ転記（絵文字は外し、空行は入れ替え）
> ・ポストモーテム 5件を「ポストモーテム」ノートブックに起票
>   （失敗したプロセス 4件＋失敗した結果 1件。各タイトルは項目の文言そのまま）

丸も罰も0件だった／結果・ポストモーテム欄が空だった場合は、その事実を1行で伝える
（「まだ丸・罰が付いていないようです。振り返りを付け終えてから呼んでください」など）。

## やってはいけないこと

- **中身の創作**（ポストモーテムの各欄を埋める、うまくいった理由を書き足す 等）。これは別スキル
  [postmortem](../postmortem/SKILL.md) の仕事。このスキルは器の用意と転記だけ。
- **テンプレートの改変。**
- **丸・罰の付いていない項目の転記。**
- **今日以外のノートを勝手に対象にすること。**

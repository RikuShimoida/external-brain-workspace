# 壁打ち結果を「なんでもメモ」へ残すスキル

オーナーは「記憶を信じず、すべてを外部脳（Evernote）へ吐き出す」人。
Claude との壁打ちで出た結論・気づき・決定も、チャットに流したまま消すのではなく、
その日の「今日やること」ノートの **なんでもメモ** 欄に残すことで、あとから必ず見返せるようにする。

このスキルは、その転記を**毎回のやり取りの締めで自動的にオファー**するための横断ルール。
（同じ趣旨は CLAUDE.md「Claude の振る舞い方」にも1項目として書いてある。両方で担保する。）

## 絶対ルール（オーナー明示の指示）

1. **壁打ち結果が出たら、なんでもメモへの記載をオファーする。** 相談・議論・思考整理・
   意思決定・アイデア出しをして「残す価値のある中身」が生まれたら、そのやり取りの締めで必ず。
2. **記載する前に必ず質問する。** 勝手に書き込まない。**「なんでもメモに記載しますか？」**と
   一言聞き、**オーナーの承認（はい/お願い 等）を得てから**書き込む。断られたら書かない。
3. **判断に迷ったら聞く。** 「これは残す価値があるか？」で迷うくらいなら、オファーする側に倒す
   （黙って流すより、聞いて断ってもらう方がオーナーの流儀に合う）。

## 何を「壁打ち結果」とみなすか

- **オファーする**：相談への結論・推奨、価値観や人物像に関する気づき、意思決定の結果、
  Podcast/note/ツイートのネタ、方針転換、「これは覚えておきたい」系の発見。
- **オファーしない**：単なる作業依頼だけで中身が残らないもの（「実装して」「マージして」
  「このファイル開いて」など、成果物はあるが"考えの結論"が無いやり取り）。
  雑談で流れて消えて構わないもの。

> 迷ったら §絶対ルール3 に従いオファー側へ。オーナーが「いらない」と言えばそれで終わり。

## 手順

### 0. 準備

必要な Evernote MCP を ToolSearch でロードする（デフォルトで出ていなければ）：

```
select:mcp__evernote__search_notes,mcp__evernote__get_note,mcp__evernote__edit_note
```

### 1. まずオーナーに質問する（書き込みより先）

やり取りの締めで、記載したい内容を **1〜3行に要約**して見せ、こう聞く：

> このやり取りの結論、なんでもメモに記載しますか？
> （要約）〇〇〇

- **承認が来るまで書き込まない。** 「はい」「お願い」等が来てから §2 へ。
- 「いらない」「今はいい」なら書かずに終了。しつこく再確認しない。
- 承認と同時に「ここも直して」等の修正指示が来たら、要約に反映してから書く。

### 2. 今日の「今日やること」ノートを特定する

- `mcp__evernote__search_notes` に `intitle:今日やること`、`clientTimeZone: Asia/Tokyo`、
  `sortBy: created` で問い合わせ、**今日の日付（YYYY年M月D日）にタイトルが一致するもの**を選ぶ。
- 今日の分が見つからない/複数該当して曖昧なときは、推測で進めずオーナーに確認。

### 3. 「なんでもメモ」欄の見出しを見つける

- `mcp__evernote__get_note(noteId)` で ENML を取る。本文は大きく（5〜6万字）、MCP の
  トークン上限で**ファイルに退避されることがある**。その場合は退避ファイルを Python 等で読み、
  見出し `なんでもメモ` を含む `<h2 ...>` タグを**バイト単位で正確に**特定する
  （チャットに全文を展開しない）。
  - 例：`<h2 style="--en-nodeId:...;"><b>なんでもメモ</b></h2>`
  - その直後にはたいてい `<div><br/></div>`（空行）が続く。

### 4. 見出し直後に要約を挿入する（append ではなく見出し直後へ）

`edit_note` の `replace` で、**「なんでもメモ」見出し（＋直後の空行）を一意アンカー**にして、
その直後へ新しい内容を差し込む。既存メモは消さず、見出しの直下（最新が上）に積む。

- `find` は `get_note` の ENML から**そのままコピー**した、見出しタグ＋直後の空行
  （`<h2 ...>なんでもメモ</h2><div><br/></div>`）。`--en-nodeId` 属性も**省略せず**含める
  （省くとマッチしない）。ENML 内で `&` は `&amp;`、`<` は `&lt;` に**必ずエスケープ**。
- `content` は「元の見出し＋空行」＋「新しい見出しと本文」＋末尾に空行、の順で組む。
  最新が見出し直下に来る形にする。

書式（例）：

```
<h2 style="--en-nodeId:XXXX;"><b>なんでもメモ</b></h2><div><br/></div>
<h3><b>（見出し：一言で何の話か）</b></h3>
<div>（本文：壁打ちの結論を2〜5行。承認された要約を素直に。捏造しない）</div>
<div>（任意）関連ファイルや根拠へのポインタ（例: podcast-ideas/2026-09-05.md）</div>
<div><br/></div>
```

- **捏造しない。** 実際にやり取りで出た内容だけを書く。無い数字や引用を足さない。
- **LINE / Gmail / Kindle 由来の第三者情報や書籍本文は書かない**（CLAUDE.md 厳守事項）。
- 他スキルの成果物（ネタ帳ファイル・decisions ログ等）があれば、その**ポインタ**を1行添える。

### 5. 完了報告（1〜2行）

チャットには要点だけ。例：

> なんでもメモに記載しました（今日やること - 2026年M月D日）。
> 見出し：「〇〇」／関連: podcast-ideas/2026-09-05.md

## 他スキルとの関係

- **decide / books / podcast-neta / note-draft / tweet-draft などの締めでも呼べる。**
  それらのスキルが本来の成果物（decisions ログ、ネタ帳ファイル等）を作ったうえで、
  「その要約をなんでもメモにも残しますか？」とこのスキルがオファーする、という重ね方をする。
- **daily-reflection とは別物。** あちらは夜の振り返り（丸・罰の転記）を機械的に処理する。
  こちらは日中の壁打ちの結論を、承認を得て「なんでもメモ」へ残す。

## やってはいけないこと

- **質問せずに書き込むこと。** 必ず「記載しますか？」→承認、の順。
- **内容の捏造・水増し。** やり取りに無いことを書かない。
- **なんでもメモ以外の欄（心得・うまくいった/失敗した 等）を触ること。** ここは日中メモ専用。
- **今日以外のノートを勝手に対象にすること。**

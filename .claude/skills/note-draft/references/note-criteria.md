# note 下書きの物差し（Podcast の下敷きを兼ねる記事）

このファイルは、外部脳から発掘したネタを **note.com にそのまま貼れる記事** に
整形するときの判断基準を定義する。note-draft スキルの本体が使う。

「どのネタを選ぶか」の物差しは
[../../podcast-neta/references/selection-criteria.md](../../podcast-neta/references/selection-criteria.md)
に従う（重複させない）。ここは選ばれたネタを **どう記事にするか** を定義する。

## 何のための note か（Issue #7）

**note 記事を書くこと自体が、そのまま Podcast で話す内容の下敷きになる**ようにする。
ラジオ専用の台本づくりは続かないので作らない。代わりに note を書けば、それが
Podcast の骨組みになっている、という一石二鳥を狙う。

導線は **note → Podcast → 開発プロダクト**。だから記事のゴールは2つ:

1. 記事単体で「この人の話、続きを **Podcast で聴いてみたい**」と思わせること。
2. その記事の流れが、そのまま **ひとり語りで話せる骨組み**になっていること。

## 「台本ではない」の意味（重要）

- 逐語的な**セリフ台本は書かない**。「えー、今日はですね…」のような口述文は不要。
- 書くのは **話の骨組み（論点の流れ）と、核になる一言**。本番はこれを見ながら
  自分の言葉で膨らませて話す前提。
- だから note は **Podcast の完全なネタバレにしない**。記事で問いを立て・引きつけ、
  「結論と深い話は Podcast で」と余白を残す。記事で全部言い切らない。

## 記事の型（1記事 = 1エピソード）

発掘したネタ（`quote` / `why` / `angle` / `theme_hint`）を、次の骨組みに落とす。

1. **フック（つかみ）** — 冒頭2〜3行。問い・意外な持論・原体験の断片で引き込む。
   前置き・自己紹介から入らない。
2. **本題（気づき / 原体験 / こだわり）** — 過去の自分の言葉（引用）を核に、
   なぜそう思うに至ったかを一人称で語る。ここが Podcast で最も膨らむ部分。
3. **問い・余白** — 読者に投げかける問い、または「この続きは Podcast で」の引き。
   結論を言い切らず、聴きたくさせる。
4. **Podcast への導線** — 末尾に軽く「この話、Podcast でもう少し深く話しました／話します」。
   押し付けない1〜2行。

## 整形ルール

- **長さは 800〜1,500 字程度**を基本（note の読みやすい1本）。長すぎたら削る。
  ネタが薄いなら無理に伸ばさない。
- **一人称・本人の口調**。過去の自分の考えを、今の言葉で言い直す。飾らない。
- **見出し（`##`）で区切る**。声に出して読める段落のリズムにする。
- **主旨を歪めない。** 元の引用の意味を保つ。言っていない主張・数字・事実を足さない。
  盛らない。過去の自分がそう考えていた範囲を超えない（捏造しない）。
- **1ネタ最大2案**まで（切り口違い）。オーナーが選べるようにする。
- 各記事に **タイトル案を2つ**添える（note のタイトルは流入を大きく左右するため）。

## やらないこと（ノイズ）

- 逐語的なセリフ台本（このスキルの趣旨に反する）。
- 記事で結論まで全部言い切ってしまい、Podcast を聴く理由を消すこと。
- 過去の自分が言っていないことを、言ったかのように書く（捏造）。
- バズ狙いの煽り・釣り。人格の信頼を損なう。
- 学習ログ・作業報告の"そのまま"転載。価値観に接続していないもの。

## 最終チェック（書き出し前の自問）

- 記事単体で「続きを **Podcast で聴きたい**」と思えるか？
- この記事の流れを見れば、**台本なしでひとり語りできる**骨組みになっているか？
- 逐語台本になっていないか（骨組み＋核の一言に留まっているか）？
- 元の引用の主旨から**逸脱していない**か（捏造していないか）？
- オーナーが声に出して読んで **恥ずかしくない**（本人らしい）か？

# 週次振り返りスキル

オーナーは毎日「今日やること - YYYY年M月D日」ノートで1日を振り返り、5つの欄
（運が良かった/運が悪かった/うまくいった/失敗プロセス/失敗結果）を埋めている。
このスキルは、**その週7枚分を横断で読み、5欄を機械的に集計して1枚のノートにまとめる**。

**このスキルは判断や創作をしない。** 各日の欄に書かれた文言を、日付を付けて右から左へ
集めるだけ。要約・言い換え・ネタ提案はしない。

## 大方針（CLAUDE.md と一致）

- **捏造しない。** ノートに無い項目を作らない。読んでいないノートを読んだことにしない。
- **記憶を外部化する。** 結果はチャットで流さず、Evernote のノート本体に書き込む。
- **一度に浴びせない。** 完了報告は2〜3行に絞る（daily-reflection の作法に合わせる）。
- **勝手に突き進まない。** create_note の前に必ず内容を提示して承認をとる。
  対象の週が曖昧なときも、実行前にオーナーへ確認する。

## 前提となるノート構造（daily-reflection と同じ実物）

「今日やること」ノートは ENML。集計に使う見出しは次の5つ。ノートにより前後の語が
ぶれるので **部分一致** で探す（集計は `scripts/weekly_reflection.py` が行う）。

1. `今日、運が良かったこと`（例: 「今日、運が良かったこと　俺のため」）
2. `今日、運が悪かったこと`
3. `今日、うまくいったこと`（例: 「今日、うまくいったことと、原因　俺のため」）
4. `今日、失敗したプロセス`（例: 「今日、失敗したプロセス、原因　俺のため」）
5. `今日、失敗した結果`（例: 「今日、失敗した結果、原因　俺のため」）

各見出しの配下＝その見出しから次の `<hr>`（または次の見出し）までの `<li>`。

集計方針（オーナー確定）:
- **重複はまとめず全件並べる。** 同じ文言が複数日に出ても各日ぶん残す。
- **各項目の先頭に必ず日付を付ける**（例: `9/5　項目テキスト`）。

## 手順

### 0. 準備

必要な Evernote MCP を ToolSearch でロードする（デフォルトで出ていなければ）：

```
select:mcp__evernote__search_notes,mcp__evernote__get_note,mcp__evernote__create_note
```

### 1. 今週（月〜日）の7日分を特定する

- 今日を基準に、その週の月曜〜日曜の7日を算出する（オーナーは月曜始まりで管理）。
  どの週を対象にするか曖昧なら、実行前にオーナーへ確認する。
- 各日について `mcp__evernote__search_notes` に
  `intitle:今日やること`、`clientTimeZone: Asia/Tokyo` で問い合わせ、
  その日の「今日やること」ノートの noteId を得る。
  - タイトルは「今日やること - YYYY年M月D日」形式と「@YYYY-MM-DD」形式の
    どちらもありうる。両方の日付表記で照合する。
- **見つからない日はスキップ**（存在する分だけ集計する）。7枚揃っていなくてよい。

### 2. 各ノートを取得して退避する

- `mcp__evernote__get_note(noteId)` で ENML を取る。本文は大きく（6万字級）、
  MCP のトークン上限で**ファイルに退避されることがある**。**チャットに全文を展開しない。**
- 退避ファイル（または JSON）を集める。`weekly_reflection.py` が読むのは
  `{title, content(ENML), created, ...}` 形式の JSON。退避ファイルがこの形でない場合は、
  各ノートの `title` と `content` を持つ JSON を1ノート1ファイルで用意する。

### 3. スクリプトで週次集計する（本体コンテキストを汚さない）

集めた JSON を `scripts/weekly_reflection.py` に渡し、レポート本文（ENML 断片）を得る：

```
python3 scripts/weekly_reflection.py <ノートJSON...> --week-monday YYYY-MM-DD
```

- `--week-monday` にはその週の月曜日付を渡す（タイトル用）。省略すると
  渡したノートの日付から最古の週の月曜を推定する。
- 出力は create_note の `content` にそのまま渡せる ENML 断片。
  - 冒頭に5見出しの週合計サマリー（各件数）。
  - 見出しごとに「計N件」＋その週の全項目（各項目先頭に日付）。
- **集計はこのスクリプトに任せる。** LLM 側で数え直したり言い換えたりしない。

### 4. 承認をとってから新規ノートを作る

- create_note の前に、**生成したレポートの要約をオーナーに提示して承認をとる**。
  提示するのは「各見出しの件数」と「見出しごとの代表項目1〜2個」程度に絞る
  （全項目を貼らない。一度に浴びせない）。
- 承認後、`mcp__evernote__create_note` で新規ノートを1枚作る：
  - タイトル：**「週次振り返り - YYYY年M月D日週」**（その週の月曜日付を使う）。
  - content：手順3で得た ENML 断片をそのまま渡す。
- 承認が得られなければ作成しない。

### 5. 完了報告（2〜3行）

チャットには要点だけ返す。例：

> 今週の振り返り、まとめました。
> ・運が良かった 4 / 運が悪かった 2 / うまくいった 3 / 失敗プロセス 3 / 失敗結果 2（計14件）
> ・「週次振り返り - 2026年8月31日週」を作成しました。

対象の週にノートが1枚も無かった場合は、その事実を1行で伝える
（「今週の『今日やること』が見つかりませんでした」など）。

## やってはいけないこと

- **中身の創作・要約の言い換え。** 各欄の文言はそのまま日付を付けて並べるだけ。
- **重複のまとめ込み。** 同じ文言でも各日ぶん残す（スクリプトがそうしている）。
- **承認前の create_note。**
- **本文全文をチャットへ展開すること。** 集計はスクリプトに隔離する。

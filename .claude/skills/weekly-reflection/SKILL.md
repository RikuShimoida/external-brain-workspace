# 週次振り返りスキル

オーナーは毎日「今日やること - YYYY年M月D日」ノートで1日を振り返り、5つの欄
（運が良かった/運が悪かった/うまくいった/失敗プロセス/失敗結果）を埋めている。
このスキルは、**その週7枚分を横断で読み、5欄を機械的に集計し、最後に総評コメントを添えて
1枚のノートにまとめる**。加えて、**失敗したプロセスに「完全一致で同じ文言」が3件以上
溜まっていたら、その文言だけポストモーテムノートを1枚起票する**（＝繰り返している失敗だけ
器を作る）。

> **ポストモーテム起票のルール変更（背景）。** 以前は日次（daily-reflection）で
> 失敗プロセスの各項目ごとに毎日ポストモーテムを起票していたが、単発の失敗まで器が量産される
> ため廃止した。いまは**週次でこのスキルが「同一文言3件以上」だけ起票する**。
> 判定は `scripts/weekly_reflection.py` が機械的に行い（完全一致のみ・言い換えや部分一致は見ない）、
> スキルは数え直さずスクリプトの出力に従うだけ。
> **失敗した結果のポストモーテムは従来どおり daily-reflection が日次で起票する（このスキルは扱わない）。**

**集計は機械的に。項目の捏造・言い換えはしない。** 各日の欄に書かれた文言は、日付を付けて
右から左へ集めるだけ（`scripts/weekly_reflection.py` が担う）。

**総評コメントだけは例外で、Claude の解釈・意見を書く。** ただし総評は集計された実項目だけを
根拠にすること（ノートに無い出来事を想像で足さない）。ポジティブな傾向を短く、そして
**失敗（プロセス／結果）については「どういう種類の失敗が多いか＝失敗の傾向」を率直に指摘する**
（オーナーは「冷静側の視点を添える」ことを求めている。遠慮して傾向をぼかさない）。

## 大方針（CLAUDE.md と一致）

- **捏造しない。** ノートに無い項目を作らない。読んでいないノートを読んだことにしない。
- **記憶を外部化する。** 結果はチャットで流さず、Evernote のノート本体に書き込む。
- **一度に浴びせない。** 完了報告は2〜3行に絞る（daily-reflection の作法に合わせる）。
- **勝手に突き進まない。** create_note の前に必ず内容を提示して承認をとる。
  対象の週が曖昧なときも、実行前にオーナーへ確認する。

## 前提となるノート構造（daily-reflection と同じ実物）

「今日やること」ノートは ENML。集計に使う見出しは次の5つ。ノートにより前後の語が
ぶれるので **部分一致** で探す（集計は `scripts/weekly_reflection.py` が行う）。

1. `今日、運が良かったこと`（例: 「今日、運が良かったこと　俺のため」）
2. `今日、運が悪かったこと`
3. `今日、うまくいったこと`（例: 「今日、うまくいったことと、原因　俺のため」）
4. `今日、失敗したプロセス`（例: 「今日、失敗したプロセス、原因　俺のため」）
5. `今日、失敗した結果`（例: 「今日、失敗した結果、原因　俺のため」）

各見出しの配下＝その見出しから次の `<hr>`（または次の見出し）までの `<li>`。

集計方針（オーナー確定）:
- **重複はまとめず全件並べる。** 同じ文言が複数日に出ても各日ぶん残す。
- **各項目の先頭に必ず日付を付ける**（例: `9/5　項目テキスト`）。

## 手順

### 0. 準備

必要な Evernote MCP を ToolSearch でロードする（デフォルトで出ていなければ）：

```
select:mcp__evernote__search_notes,mcp__evernote__get_note,mcp__evernote__create_note,mcp__evernote__edit_note,mcp__evernote__search_notebooks
```

（`edit_note` と `search_notebooks` は §6 のポストモーテム起票で使う。起票対象が0件なら不要。）

### 1. 今週（月〜日）の7日分を特定する

- 今日を基準に、その週の月曜〜日曜の7日を算出する（オーナーは月曜始まりで管理）。
  どの週を対象にするか曖昧なら、実行前にオーナーへ確認する。
- 各日について `mcp__evernote__search_notes` に
  `intitle:今日やること`、`clientTimeZone: Asia/Tokyo` で問い合わせ、
  その日の「今日やること」ノートの noteId を得る。
  - タイトルは「今日やること - YYYY年M月D日」形式と「@YYYY-MM-DD」形式の
    どちらもありうる。両方の日付表記で照合する。
- **見つからない日はスキップ**（存在する分だけ集計する）。7枚揃っていなくてよい。

### 2. 各ノートを取得して退避する

- `mcp__evernote__get_note(noteId)` で ENML を取る。本文は大きく（6万字級）、
  MCP のトークン上限で**ファイルに退避されることがある**。**チャットに全文を展開しない。**
- 退避ファイル（または JSON）を集める。`weekly_reflection.py` が読むのは
  `{title, content(ENML), created, ...}` 形式の JSON。退避ファイルがこの形でない場合は、
  各ノートの `title` と `content` を持つ JSON を1ノート1ファイルで用意する。

### 3. スクリプトで週次集計する（本体コンテキストを汚さない）

集めた JSON を `scripts/weekly_reflection.py` に渡し、レポート本文（ENML 断片）を得る：

```
python3 scripts/weekly_reflection.py <ノートJSON...> --week-monday YYYY-MM-DD
```

- `--week-monday` にはその週の月曜日付を渡す（タイトル用）。省略すると
  渡したノートの日付から最古の週の月曜を推定する。
- 出力は create_note の `content` にそのまま渡せる ENML 断片。
  - 冒頭に5見出しの週合計サマリー（各件数）。
  - 見出しごとに「計N件」＋その週の全項目（各項目先頭に日付）。
  - **末尾に「ポストモーテム起票対象（失敗プロセスで完全一致3件以上）」ブロック**。
    失敗プロセスの中で**完全一致の同じ文言が3件以上**あったものだけを `<li>文言（N件）</li>`
    で列挙する（0件なら「（なし）」）。**§6 はこのブロックの各文言をそのまま起票対象にする。**
- **集計と起票判定はこのスクリプトに任せる。** LLM 側で数え直したり言い換えたりしない。
  「同じ失敗が3件以上か」も自分で数えず、スクリプトが出した起票対象ブロックに従う。

### 3.5. 総評コメントを書く（Claude の解釈）

手順3で得た集計結果（実項目）だけを根拠に、末尾へ付ける総評コメントを Claude が書く。
**ここだけは集計と違い、Claude の意見を書いてよい。** ただし実項目に無い出来事は足さない。

- **ポジティブ**：うまくいった／運が良かったの傾向を1〜2文で短く。
- **ネガティブ（重点）**：失敗プロセス／失敗結果を見て、**どの種類の失敗が多いか＝傾向**を
  具体的に指摘する。似た失敗をグループにまとめ、繰り返しがあれば回数も添える
  （例：「買い物・確認ミスが結果失敗5件中4件」「思い込みで確認・共有を飛ばすパターン」など）。
  遠慮して傾向をぼかさない。率直に。ただし人格否定ではなく「傾向の指摘」に徹する。
- 失敗が0件の週は、ネガティブ側は「今週は失敗の記入なし」とだけ書く（無理に粗探ししない）。
- ENML 断片で組む。見出しは `<div><b>総評（YYYY/M/D〜M/D）</b></div>`、本文は `<div>…</div>`。

### 4. 承認をとってから新規ノートを作る

- create_note の前に、**生成したレポートの要約＋総評をオーナーに提示して承認をとる**。
  提示するのは「各見出しの件数」と「総評コメント全文」、そして
  **ポストモーテム起票対象があれば、その文言と件数（例: 「確認を飛ばした（3件）」）**に絞る
  （全項目は貼らない。一度に浴びせない）。総評はオーナーが一番読みたい部分なので必ず見せる。
- この承認は **週次ノートの作成と §6 のポストモーテム起票をまとめて確認する**もの。
- 承認後、`mcp__evernote__create_note` で新規ノートを1枚作る：
  - タイトル：**「週次振り返り - YYYY年M月D日週」**（その週の月曜日付を使う）。
  - 本文：`create_note` は空ノートを作るので、`mcp__evernote__edit_note`（mode: append）で
    **手順3の集計 ENML 断片 → 手順3.5の総評 ENML 断片 の順**に追記する（総評が末尾）。
  - ENML の注意：`content` は整形式 XML。裸の `&` は `&amp;`、`<` は `&lt;` に必ずエスケープ。
- 承認が得られなければ作成しない。

### 5. ポストモーテム起票（失敗プロセスで完全一致3件以上のものだけ）

§3 のレポート末尾「ポストモーテム起票対象」ブロックに**文言が挙がっていれば、その各文言ごとに
1枚**ポストモーテムノートを作る（下の手順）。**「（なし）」なら本ステップはスキップ。**
§4 の承認に含まれているので、承認後にそのまま起票してよい。

- タイトルは**起票対象ブロックの文言そのまま**（末尾の「（N件）」は付けない）。
- **テンプレートは無修正・中身も埋めない。** 器を作るだけ（daily-reflection と同じ思想）。
- 数はスクリプトの出力に従う。**自分で「3件以上か」を数え直さない。**

**ポストモーテムノートの作り方（テンプレートを丸ごと複製）**：Evernote MCP の `create_note` は
空ノートしか作れずテンプレート指定ができないので、「ポストモーテム」テンプレート本体の ENML を
複製して流し込む（daily-reflection の §7 と同一手順）。複数枚起票するときも、テンプレート ENML の
取得と保存先ノートブック GUID の取得は最初の1回だけでよい。

1. **テンプレート本体を取得**：`search_notes("intitle:ポストモーテム")` で `isTemplate:true` の
   ノート（タイトル「ポストモーテム」）を `get_note` し、ENML を取る。
2. **保存先ノートブックの GUID**：`search_notebooks("ポストモーテム")` でノートブック
   「ポストモーテム」の `notebookId` を得る。
3. **空ノートを作る**：`create_note({ title: <文言そのまま>, notebookId: <上の GUID> })`。
4. **中身を流し込む**：手順1のテンプレート ENML 本体（`<en-note>` の中身。
   `<?xml>`/`<!DOCTYPE>`/`<en-note>` タグ自体は付けない）を
   `edit_note({ noteId, mode: "append", content: <テンプレートの中身> })` で入れる。
   ENML が大きければ数回に分けて `append` する。**テンプレートは修正しない・中身も埋めない。**

### 6. 完了報告（2〜3行）

チャットには要点だけ返す。例：

> 今週の振り返り、まとめました。
> ・運が良かった 4 / 運が悪かった 2 / うまくいった 3 / 失敗プロセス 3 / 失敗結果 2（計14件）
> ・「週次振り返り - 2026年8月31日週」を作成しました。
> ・繰り返し失敗（3件以上）のポストモーテムを 1件起票（「確認を飛ばした」）。

ポストモーテム起票対象が0件だった週は、その旨を1行添える（「今週は同じ失敗プロセスの
3件以上の繰り返しは無し」など）。
対象の週にノートが1枚も無かった場合は、その事実を1行で伝える
（「今週の『今日やること』が見つかりませんでした」など）。

## やってはいけないこと

- **集計項目の創作・言い換え。** 一覧の各文言はそのまま日付を付けて並べるだけ。
- **総評での捏造。** 総評は集計された実項目だけを根拠にする。ノートに無い出来事を想像で足さない。
- **重複のまとめ込み。** 同じ文言でも各日ぶん残す（スクリプトがそうしている）。
- **承認前の create_note。**
- **本文全文をチャットへ展開すること。** 集計はスクリプトに隔離する。
- **起票対象を自分で数え直す・言い換えでまとめる・部分一致で拾うこと。** 起票対象はスクリプトが
  出した「完全一致3件以上」のブロックがすべて。3件未満の失敗や単発の失敗に器を作らない。
- **ポストモーテムテンプレートの改変・中身の記入。** 器を作るだけ（中身埋めは別スキル postmortem）。
- **失敗した結果からの起票。** それは daily-reflection の担当。このスキルは失敗プロセスだけ扱う。

# 意思決定アドバイザー スキル

オーナーの外部脳（Evernote の価値観・目標ノート）に照らして、目の前の選択を
**「オーナーらしさ」で採点し、推奨を1つ出す**。そして判断過程を外部脳（`decisions/`）に残す。

狙いは、一般論のアドバイスではなく **本人が過去に言語化した価値観と整合した判断** を返すこと。
判断の物差しは [references/decision-criteria.md](references/decision-criteria.md) に蒸留済み。

## 大方針（CLAUDE.md と一致）

- **勝手に決めない。** 選択肢や前提が曖昧なら本人に確認する（一度に聞くのは2〜3個まで）。
- **捏造しない。** 引用・根拠は必ず実在するノートに紐づける。原典タイトルを添える。
- **推奨は1つに絞る。** 長大な列挙をしない。平易に、噛み砕いて。
- **重い走査は隔離。** ノートを何件も全文読む必要がある大きな決定のときだけサブエージェントに逃がす。
- **過去の自分の判断を必ず見る**（手順 1.5）。前と逆の推奨を黙って出さない。

## 手順

### 0. 決定の明確化
- 何を選ぶ問題か、選択肢は何かを確認する。曖昧なら本人に聞く（2〜3個に絞って）。
- 決定の性質を把握する（採点軸の出し分けに使う）:
  - **お金がかかるか**（→ 軸 C を使う）
  - **家族が絡むか**（→ 軸 B の家族側・軸 E を使う）
  - **キャリア／住む場所か**（→ ノート「これからのキャリア選択肢」を必ず参照）
  - **挑戦 vs 現状維持か**（→ 軸 D を使う）

### 1. 判断基準の読み込み
[references/decision-criteria.md](references/decision-criteria.md) を Read する。これが一次の物差し。
毎回 Evernote を重く走査しない（速く・決定的に）。

### 1.5. 過去の判断を読む（採点に入る前に必ず）

`decisions/` には**過去に自分がどう判断したか**が残っている。これを見ないと、
同じ選択で前と逆の推奨を出したり、一度決めた前提を無視したりする。

```bash
python3 scripts/output_map.py
```

`outputs-archive/output_map.tsv` の `kind` が `decision` の行が過去の判断ログ
（`label` が決定の題、`quote` が根拠に使った本人の言葉）。今回の決定と関係する行を探す。

- **同じテーマの判断が過去にあるなら、必ず本文（`file` 列のパス）を Read する。**
  そのときの推奨・確認したい問い・冷静側の一言まで読む。
- 今回の推奨が過去と**食い違うなら、食い違うこと自体を明示する**。
  「前回は〇〇を選んだが、△△が変わったので今回は違う」と書く。黙って上書きしない。
- 過去に「決める前に確認したい問い」を残していたなら、**それが解けたかを先に確認する**。

判断の一貫性を見るのが目的なので、`kind` が `podcast` / `tweet` / `note` の行は無視してよい
（あちらは既出ネタの重複回避用）。

### 2. その決定に効く"実在の言葉"を取りに行く
決定テーマに合わせて Evernote を **targeted に** `semantic_search` する。
目的は採点の裏づけになる **本人の実際の引用を1〜3個** 拾うこと。

- 例のクエリ:
  - キャリア/住む場所 → 「これからのキャリア選択肢」「なりたい肩書き」
  - お金/買い物 → 「お金の使い方 哲学」「人生に必要なものの取捨選択」
  - 挑戦するか迷い → 「フーファイターズ 逆 現状維持 後悔」
  - 幸せ/生き方全般 → 「幸せの5大要素」「2026年成長したマインド」
- ヒットしたら `get_note` で該当箇所だけ確認し、短い引用を採る。**なければ無理に引用を作らない。**
- ノートを何件も全文読む必要がある大きな人生決定のときだけ、`Explore`/`general-purpose`
  サブエージェントに読み込みを隔離して要約だけ受け取る（本体コンテキストを汚さない）。

### 3. 採点
[references/decision-criteria.md](references/decision-criteria.md) の軸（A〜F ＋タイブレーカー）で
各選択肢を短評する。

- **全軸を無理に使わない。** その決定に効く軸だけを選ぶ。
- 各軸 ◎（強く後押し）/ ○（後押し）/ △（中立〜要注意）/ ×（逆行）＋一言。
- 表は簡潔に。選択肢が多いなら本人と相談して2〜3個に絞る。

### 4. 推奨
- **推奨は1つに絞る。** 理由を、軸の採点と **本人の言葉の引用**（実在ノート）で裏づける。
- **「決める前に本人に確認したい問い」を1つだけ** 添える。
- 本人のテンションが高そうなら、冷静側の視点を一言添える（高テンション時はミスが増える自覚あり）。
- 採点が拮抗したらタイブレーカー（座右の銘）を最後に効かせる。

### 5. 記録（外部化）
判断過程を `decisions/YYYY-MM-DD-<短い題>.md` に保存する。

- **保存前に一声かける**（「この内容で `decisions/…md` に残していい？」）。
- 書き出す内容: 決定の題／選択肢／使った軸と採点表／引用根拠（原典タイトルつき）／推奨／確認したい問い。
- 過去の判断と関係するなら、**`## 過去の判断との関係`** の節を足して
  「どの判断ログと繋がるか／今回どこが変わったか」を1〜2行で残す（次回これを読むため）。
- `decisions/` が無ければ作る。保存後に**パスを明示**する（本人が後で辿れるように）。
- 日付は環境の現在日付を使う。題は短く（ファイル名に使えない文字は避ける）。

## 出力フォーマット（チャット）

```
## 決定: <題>
選択肢: A) … / B) …

### 採点（効く軸だけ）
| 軸 | A) … | B) … |
|---|---|---|
| A なりたい自分像 | ◎ …一言 | △ …一言 |
| C お金の哲学 | ○ …一言 | × …一言 |
| …（効く軸だけ） | | |

### 本人の言葉から
> 「<実在ノートからの短い引用>」 —（出典: ノート「…」）

### 推奨: <1つ>
理由: …（軸と引用で裏づけ）
決める前に確認したい問い: …（1つだけ）
```

保存後に `decisions/YYYY-MM-DD-<題>.md` のパスを伝えて締める。

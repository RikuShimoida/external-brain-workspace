# 漫画ストーリー壁打ちスキル

オーナー（下井田陸）は漫画原作者志望。Evernote の「漫画のアイデア」ノートブック（約223件）に
断片的なネタが大量に眠っている。このスキルは、その外部脳を引きながら壁打ちし、
**散らばった過去ネタを一本の企画に統合する**ための型。

狙いは「新しいネタをゼロから出す」ことではなく、**すでに何度も書いている本人の芯**
（報われなかった側・記憶・殻を破る・家族への愛）を拾い直し、作品の背骨にすること。

## 大方針

- **勝手に突き進まない。** 探索範囲・提案・ノートへの書き込みの前は必ず一声かける。
- **冷静側の視点を必ず1つ添える。** 盛り上がっているときほど「盛りすぎ」「既視感」「実行の壁」を1点だけ差し込む。
- **一度に渡す選択肢は2択まで。** オーナーは3つ以上を同時に保持できない。分割する。
- **ネタや引用を捏造しない。** 過去ノートの引用は必ず実在するノートに紐づける。読んでいないノートを読んだことにしない。
- 作法の詳細は [references/craft-principles.md](references/craft-principles.md) に従う。

## データソースの扱い（厳守）

漫画アイデアは Evernote の **「漫画のアイデア」ノートブック1つ**に固まっている。
このノートブックが今回の母集団。詳細は [docs/data-sources.md](../../../docs/data-sources.md)。

- **Evernote には2実装がある。使うのは claude.ai コネクタ側（`mcp__Evernote__*`、大文字E）。**
  `.mcp.json` の `evernote`（小文字）は OAuth で、非対話クラウドセッションでは proxy 403 で接続失敗する。
  クラウド（Claude Code on the web）では**コネクタ側だけが使える**。`ToolSearch` で
  `mcp__Evernote__semantic_search` `mcp__Evernote__search_notes` `mcp__Evernote__get_note`
  `mcp__Evernote__create_note` `mcp__Evernote__edit_note` をロードする。
- **「検索」と「列挙」の2経路を両方走らせる。**
  1. `semantic_search` でテーマを変えて複数回投げる（意味で拾う）。
  2. `search_notes` に `notebook:"漫画のアイデア"` を渡して**全件列挙**する（母集団の地図代わり）。
     `totalResultCount` を見て `startIndex` でページングし、取りこぼさない。
  - ローカルの `evernote-archive/note_map.tsv`（地図経路）はクラウドには無い。だが漫画アイデアは
    単一ノートブックに固まっているので、上記の**ノートブック全件列挙が地図の代わり**になる。
- 気になったノートは `get_note` で本文（ENML）を取り、`殴り書き、メモ` 欄の実際の言葉を拾う。

## 手順

### 0. 前提確認
- 作業ディレクトリは repo ルート想定。
- コネクタ Evernote が使えるか確認する。使えなければ「今日は口頭の壁打ちだけにする／手元の対話セッションで
  やり直す」のどちらかをオーナーに確認する（クラウドでコネクタが落ちているときは書き込みもできない）。

### 1. 母集団を押さえる（発掘）
- 「漫画のアイデア」ノートブックを `semantic_search`＋`notebook:` 全件列挙で拾う。
- オーナーが今出しているネタ（殴り書き）と**マージできる過去ノート**を数本に絞って提示する。
  - **全部乗せにしない。** 近いもの上位だけ。世界観がぶつかるものは「キャラ/魂だけ吸収」に留める。

### 2. 壁打ちで一本に育てる
- テーマ → 主人公 → 構造 → 泣き所 → トーン、の順で背骨を立てる。
- 各ステップで [references/craft-principles.md](references/craft-principles.md) の作法を効かせる
  （冷静側1つ／2択まで／参考を模倣にしない＝天井 vs 実現／オーナーの芯への接続）。
- 迷う分岐は必ずオーナーに投げる。勝手に確定しない。

### 3. 企画メモに残す（書き込みは承認必須）
- まとまったら「漫画のアイデア」ノートブックに**新規ノート**を作り、既存の
  「漫画アイデアテンプレート」形式（`キャラクター` / `殴り書き、メモ` / `あらすじ（自分で）` /
  `イメージソング` 等）の各欄へ流し込む。
- **書き込む前に必ず「このノートに書き込んでいい？」と質問し、承認を得てから書く。** 勝手に書かない。
- 手順: `create_note`（`notebookId` 指定、空ノートが返る）→ `edit_note` で各欄を `replace`/`append`。
  上書き事故を避けるため、既存ノートに書くときは先に `get_note` で中身を確認する。

### 4. 締め（"売れそう?"ループに入らない）
- 企画は設定をいくら盛っても「売れる」の勝率は動かない。**次の一手は必ず「1話のつかみ」**に向ける
  （確証は描いた後にしか来ない）。オーナーが完璧主義で動けなくなる罠に嵌らないよう、冷静に背中を押す。

## braindump-to-memo との住み分け

- **manga-brainstorm**：作品の**企画**そのもの → 「漫画のアイデア」ノートブックへ。
- **braindump-to-memo**：その日の汎用の気づき/決定 → 「今日やること」ノートの**日記**欄へ。
- 漫画の壁打ちで「作品と関係ない一般的な学び/決定」が出たら、それだけ braindump-to-memo でオファーしてよい。
  企画本体を「日記」に丸ごと写す必要はない（二重管理になる）。
